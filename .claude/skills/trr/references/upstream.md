# Upstream contribution boundary

Read this at step 7, once a TRR is merged here and someone wants it to reach the external
projects. The short version: **you prepare, the person files.** This page explains why that
line exists and what "prepare" concretely means; the authoritative, always-current filing
mechanics live in the repo-root `UPSTREAM.md`, which is regenerated from `research/index.json`.

## Why filing is a human step

A finished TRR fans out to three third-party projects — the research report to
[tired-labs/techniques](https://github.com/tired-labs/techniques), the Sigma rule(s) to
[SigmaHQ/sigma](https://github.com/SigmaHQ/sigma), and the emulation test to
[redcanaryco/atomic-red-team](https://github.com/redcanaryco/atomic-red-team). Opening those
pull requests is deliberately left to the person, for reasons that are about correctness and
good citizenship, not permission plumbing:

- **The PR is a public act of authorship under a real identity.** It carries a contributor
  name (`Jason Vasquez`, not `det-eng`), shows up on the person's GitHub account, and starts a
  conversation with maintainers they'll be expected to answer. That identity and that dialogue
  are the person's to own.
- **Maintainer review is a human-to-human negotiation.** Each project pushes back on scope,
  naming, log-source placement, tag form, GUID assignment. Those threads need a person who can
  make judgment calls and commitments, not an agent firing one-shot PRs into a repo it doesn't
  maintain.
- **Unsolicited automated PRs are a burden on volunteer projects.** All three are
  community-run. The respectful default is to arrive as a human contributor who has done the
  conformance work, not as a bot.
- **One contribution per PR, reconciled against the current spec.** Each project's linter and
  format spec move; a wave of PRs should be filed deliberately, re-checking each gate at filing
  time (`UPSTREAM.md` records when the specs were last reconciled). This is a decision point,
  not a batch job.

None of the three requires a DCO sign-off or a CLA (verified 2026-10-13: tired-labs is
GPL-3.0, SigmaHQ rules are DRL-1.1, Atomic Red Team is MIT). So the boundary is not a legal
gate — it's the authorship-and-stewardship one above.

## What "prepare" means (the agent's half)

Everything up to the fork-and-PR is fair game and is where the leverage is. On the person's
word, transform the locally-merged artifacts into the exact shape each upstream gate expects:

- **The transformed trees / batches**, per the step-by-step transforms in `UPSTREAM.md`:
  the `reports/trr0000/<platform>/` tired-labs tree (ID remapped to the `trr0000` placeholder,
  detection sections stripped, re-wrapped to ≤80 chars, links made reference-style, DDMs
  re-rendered so their stamped hash matches); the per-log-source SigmaHQ rule set (placed by
  `logsource`, tags normalised, escaped-wildcard matches reworked); the ART merge-or-new-file
  per technique (existence-checked, GUIDs handled, internal references scrubbed).
- **Run every conformance gate locally** and report the result, so the person files from green:
  the tired-labs `trrlint` + index merge-test, SigmaHQ's real `sigma check --fail-on-error
  --fail-on-issues` with the SigmaHQ validators + `yamllint -s` + `test_logsource.py`, and the
  ART `runner.py validate`.
- **The filing plan**: which PR goes where, in what order, one technique per PR, with the
  PR-template fields drafted.

Then hand it over. Present the prepared artifacts and the plan; let the person fork and open the
PRs under their account. Don't open, push to, or comment on the external repos yourself — that
holds even when a PR here is merged and "ready," and even if asked offhandedly; confirm the
person actually wants to file before doing the prep wave, and never cross from prep into filing.

## Pointer

`UPSTREAM.md` (repo root) is the live checklist: the three-destination map, the SigmaHQ
log-source paths, the readiness table (regenerated by `research/tools/upstream_report.py`), the
conformance-gate commands and their current results, and the numbered submission steps per
project. Read it when preparing a wave — it is more current than this page by design.
